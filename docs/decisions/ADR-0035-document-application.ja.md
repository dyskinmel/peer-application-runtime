# ADR-0035 文書適用と署名付き受理を別々の表で追跡

状態: 候補。元仕様不変。L-WP04/V-WP04で局所試験。

既存の認可付きStoreの監査はenvelopes.state=pendingを受理ログの条件に持つ。ここをappliedへ書き換えると旧監査契約と互換性が壊れる。受信者が新しいnonceや自分の署名を作って他者の変更を自己コミットとして再生成するのも誤り。

そこでschema4の同じDB内に原データ・適用イベント・文書frontierを設ける。公開JSONのappliedフラグは権威ではない。AEADのAADは入力集合・engine・認可先端・文書版・操作ID・nonce発行情報へ結合する。新規受信データは原署名のまま保存し、旧commit_ledger/actor stateへ偽の自己書き込みは作らない。

実Automerge未取得のため実行済みクラスはcandidateのみ。通常経路はテスト用coreを拒否する。実core用候補では正確な適用集合とnote型を検証できた場合のみ別クラスにするが、この分岐は未実証。製品Gate/共有UIは未認定のまま。

バックアップやAPIの利用者はこのStore版を明示的に選択する必要がある。旧版の自動上書き移行は禁止。将来、native実装/CRDT試験が成立した後に正式な永続形式を決める。安全なrollback耐性・秘密鍵復旧・multi-epoch・GCは本ADRだけでは解決しない。
